DSM 2024 Settlement Engine

I turned the CERC Deviation Settlement Mechanism Regulations, 2024 into a requirements pack and a working settlement engine. The pack covers the problem, stakeholders, process, 49 traceable business rules, user stories, a gap log, and a regression suite. The engine prices every 15-minute block for generators, renewables, storage and buyers.

Source: CERC No. L-1/260/2021/CERC · 05 Aug 2024 Repeals DSM Regulations 2022 96 time blocks / day Band 49.90–50.05 Hz
01 · Context

Why this matters to a power-tech company

Every grid-connected regional entity is scheduled block by block. Any gap between schedule and actual metered energy is a deviation. Under the 2024 rules it is priced by frequency, volume slab and entity type, then settled every week through the Regional Power Committee. Forecasting, scheduling and QCA platforms are judged on one number: the client's DSM bill. A product team needs a precise, testable spec of these rules before building forecasting, bidding or settlement-audit features.

Problem

Clients often receive the weekly DSM statement with no independent way to check it. The 2024 rules add WS-seller denominators that change from 01-04-2026, new buyer categories for RE-rich states, and ESS sign inversion. Spreadsheet checks break every time the rules change.

Objective

Specify and prototype a rule-driven engine that reproduces RPC statements to the rupee, explains each charge by clause, and estimates DSM exposure before scheduling. This gives forecasting teams a cost to minimise in place of an error percentage.

Success measures

  • Reconciliation variance vs RPC statement ≤ 0.1%
  • Each rupee traced to a rule ID and clause
  • A rule change ships as configuration, without a code release
  • Weekly audit done in under 30 minutes per entity

07 · Backlog

User stories and acceptance criteria

US-01 · Audit the weekly statement Must

As a settlement analyst at a generator, I want to upload the RPC weekly statement and my SEM data so that I can dispute wrong charges before the 10-day payment deadline.

Given SEM data and schedules for 672 blocks (7 × 96)
And the RPC statement for the same week
When I run the reconciliation
Then each block shows engine ₹, RPC ₹ and the variance
And blocks with variance above ₹1 are flagged with the rule ID
And the days left until the due date are shown

US-02 · Cost-aware scheduling Must

As a forecasting manager at a QCA, I want the expected DSM cost of each schedule revision so that I revise only when the saving beats the effort.

Given a forecast distribution for block 52
When I compare schedule options 62 MW and 66 MW
Then the expected DSM cost of each is shown
And the VL1 / VL2 limits in MW are drawn on the chart

US-03 · Regime switch on 01-04-2026 Must

As a product owner, I want the WS denominator and volume limits to switch by block date so that history and the current week are priced under the right regime.

Given a block dated 31-03-2026 23:45
Then the denominator is Available Capacity and solar VL1 = 10%
Given a block dated 01-04-2026 00:00
Then the denominator is X%·AvC + (100−X)%·S and solar VL1 = 5%
And X is read from configuration with an effective date

US-04 · Outage protection Should

As a plant operator, I want a forced outage to be charged at RR for up to 8 blocks so that I am not billed the 150–200% penalty while the schedule is being revised.

Given a forced outage logged at block 30
And the schedule is revised from block 36
Then blocks 30–35 are charged at RR (BR-OT-01)
And from block 36 normal rules apply

US-05 · ESS charging inversion Should

As a storage operator, I want over-drawal while charging to count as under-injection so that my ESS is priced as Reg 8(5) requires.

Given the ESS is in charging mode
When it draws 5 MW more than scheduled
Then it is priced as a 5 MW under-injection on the general-seller table

US-06 · Rule configuration Could

As a business analyst, I want slab limits and rate percentages stored as dated configuration so that a CERC amendment is a data change that QA can test without a code release.

Given CERC notifies X = 60% from a date
When I add the config row with that effective date
Then the regression suite runs, and blocks on or after that date use 60%

  • Price 672 blocks × 500 entities in under 60 s
  • Effective-dated, versioned rule configuration with an audit trail
